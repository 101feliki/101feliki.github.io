About me

Backend & DevOps engineer who cares about what happens after launch

I'm Felix Kariuki, based in Nairobi. I build APIs and databases, then deploy and run them: containers, servers, CI, monitoring and backups. I like the unglamorous parts: monitoring, backups, access control and documentation that a new teammate can actually follow.

My story

I started with the freeCodeCamp back-end curriculum, building small Node.js services: a timestamp microservice, a chat app, a movie watchlist API with JWT authentication. That habit of shipping small, working things stuck.

My first professional role was a software engineering internship at Birdview Microinsurance (Nov 2025 – Jan 2026), where I built a facial recognition attendance system for 50+ staff, financial transaction workflows with audit trails, a customer notification platform and an asset registry.

Today I'm a backend engineer at BCK Inno Works, where I build systems for client companies. For Mustek East Africa, a hardware distributor, I own the API and the production server: catalogue, orders, careers, staff roles, a security dashboard with an attack map, and privacy-first personalisation. For Movit, I built an attendance system that replaces a paper HR form, and a sales-returns portal wired into Freshservice and Freshsales.

Alongside work I'm building Stayvinci, a multi-tenant booking platform, and studying for a BSc in Computer Science at Zetech University. I'm especially interested in insurance technology and security, which is where projects like the fraud detection service, InsureLog and AEGIS come from.

What I'm good at

  • Designing REST APIs and PostgreSQL schemas that stay fast as data grows
  • Hardening systems: least-privilege access, rate limits, audit trails, attack monitoring
  • Integrating business tools: Freshservice, Freshsales, Microsoft Entra ID, email and SMS
  • Networking and systems: TCP/IP, DNS, DHCP, VLANs, VPN, routing and switching; Linux and Windows administration
  • Running production: Docker, nginx, pm2, TLS, backups and zero-surprise deploys
  • Explaining technical decisions in plain language to non-technical clients
